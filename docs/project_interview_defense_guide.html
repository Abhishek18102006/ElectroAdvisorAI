🎯 1. Executive Summary & 30-Second Elevator Pitch

The 30-Second Interview Pitch:
"I built ElectroAdvisor, an intelligent conversational sales assistant for electronics. When customers shop for tech, they know their practical goals—like 'I need a laptop for college machine learning experiments and campus commute on an ₹80,000 budget'—but rarely know the specific hardware specifications they need. Generic LLMs often hallucinate prices or fake specs, while ecommerce filters are dumb and rigid. ElectroAdvisor bridges this gap by combining an asynchronous FastAPI backend and React frontend with a stateful recommendation agent. It translates natural language goals into strict hardware rules, enforces hard budget caps in deterministic Python code so it never overspends, and recommends the top 2 products with explicit trade-off comparisons grounded in a real 50-item database."
❌ Why Naive LLMs & Chatbots Fail
  • Hallucinations: LLMs invent fake model names, discontinued laptops, or fictitious prices.
  • Budget Violations: Prompts like "around 80k" frequently output ₹95k or ₹1.2L items.
  • Excessive Interrogation: Chatbots ask 15–20 robotic survey questions in a row.
  • API Fragility: Vulnerable to network stalls, rate limits, and quota tireout.
✅ How ElectroAdvisor Solves This
  • Strict Separation: LLM only extracts structured entities; deterministic code filters & scores.
  • Deterministic Budget Caps: Hard constraint eliminates over-budget items before scoring.
  • Decision Graph: Evaluates information sufficiency; stops questioning once essentials are known.
  • Dual-Mode Failover: 5.0s timeout with instant fallback to regex rules in <5ms.

🔄 3. The 5-Step Runtime Request Flow

When a user sends a message (e.g., "Around ₹80,000. Mostly local experiments, and I carry it around campus."), the system processes it in five distinct steps:

  1. Step 1: NLP Entity Extraction (extractor.py) — Translates unstructured customer text into a structured Pydantic schema (budget_max: 80000.0, primary_uses: ["machine_learning"], local_ml: True, portability: True). Uses Gemini 1.5 Flash or OpenAI with a strict 5.0s timeout, falling back to a deterministic regex engine.
  2. Step 2: State Tracking & Mind-Change Reconciliation (state.py) — The StateManager merges the new entities into persistent conversation memory. If the customer updates a previously stated requirement (e.g., lowering budget from 80k to 60k), it overwrites the field while preserving earlier context.
  3. Step 3: Decision Graph Orchestration (orchestrator.py) — Evaluates information completeness. If essential fields are missing (e.g., use case or budget), it halts and asks one focused follow-up question. If requirements are sufficient, it immediately transitions to recommendation.
  4. Step 4: Two-Stage Filtering & Ranking (filter_rank.py):
    • Stage 1 (Hard Constraint Filter): Automatically disqualifies products where price > budget_max or where local ML is requested but dedicated GPU is missing.
    • Stage 2 (Soft Preference Ranking): Computes a 0–100 utility score: Use-Case Fit (40 pts) + Portability (20 pts) + Battery (15 pts) + Customer Rating (15 pts) + Value (10 pts). Selects the Top 2 complementary models.
  5. Step 5: Rationale & Trade-Off Generation (explainer.py) — Formats spec-accurate explanations directly from database fields (zero hallucinations) and generates a structured side-by-side trade-off matrix across Graphics, Portability, Battery, and Price.

🛡️ 5. Key Edge Cases & Reliability Hardening

Highlights to Mention in Your Interview:
  • 50 Generalised Records: Expanded catalog from 23 to 50 realistic records across 5 categories, verified by automated tests.
  • Strict LLM Timeout Safety: Added configurable LLM_TIMEOUT_SECONDS=5.0. Rather than worrying about API key rotation or exhaustion heuristics, the agent cancels stalled LLM calls after 5s and falls back cleanly to deterministic rules.
  • Playwright Headless Browser Fix: Diagnosed CDN mirror 404s, installed official Playwright driver binaries (npx playwright install chromium), and verified sandbox network egress and browser compatibility via npm run test:e2e.
  • Indian Currency Parsing: Handles ₹1,20,000, 1,20,000 INR, 80k, and 1.5 lakh without regex crashes.
  • Mind Changes: Customer can reduce their budget mid-chat (e.g. ₹80k $\rightarrow$ ₹60k); state updates immediately and computes dynamic alternatives.
  • Category Isolation: Switching from laptop to monitor clears RAM and GPU hard constraints so monitor recommendations aren't blocked.
  • Honest No-Match Fallback: If a customer requests impossible constraints (e.g. RTX 4090 under 30k), it outputs an honest database-computed explanation with real alternatives instead of hallucinating.

🎯 8. HR & Technical Interview Q&A Cheatsheet

Q1: "Why did you use FastAPI instead of Flask or Django?"
Answer: "FastAPI is natively asynchronous (ASGI), which is critical for AI agents making non-blocking calls to external LLMs and databases. It also provides automatic Pydantic request/response validation and auto-generates interactive Swagger API documentation at /docs, saving significant engineering overhead."
Q2: "Why didn't you let the LLM generate SQL queries directly?"
Answer: "Allowing an LLM to generate raw SQL poses severe security risks like SQL injection, and reliability risks like hallucinated tables or malformed syntax. In ElectroAdvisor, tool execution is strictly controlled through parameterized SQLAlchemy ORM queries in app/agent/tools.py. The LLM only extracts structured parameters, which are validated before querying."
Q3: "How do you guarantee the AI never recommends products above the customer's budget?"
Answer: "We use a two-stage recommendation pipeline. Maximum budget is enforced as a hard constraint in Stage 1. Any product where price > budget_max is strictly disqualified in Python code before scoring even begins. An over-budget product can never reach the soft ranking stage regardless of its features."
Q4: "What happens if the Gemini or OpenAI API times out or fails?"
Answer: "As emphasized during our architecture review, we prioritize strict timeout guarantees over API key tireout heuristics. We enforce an async timeout of LLM_TIMEOUT_SECONDS=5.0. If an LLM call exceeds 5s, the coroutine is cancelled immediately, logged, and seamlessly falls back to our deterministic rule extractor in less than 5ms with zero disruption to the user."
Q5: "How did you test your system?"
Answer: "We built a test suite of 40 automated pytest tests covering all 12 endpoints, state memory, mind-changes, currency parsing, and timeout fallbacks. We also wrote an automated Playwright E2E headless browser test (npm run test:e2e) verifying external network access and local React asset rendering."
